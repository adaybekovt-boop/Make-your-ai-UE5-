# Map input isolation and wheel packets

Incremental pass after `5d28d65e1fc32bf5c89ac8b7bc81eb2004fa8207`.

Camera input handlers previously ran without checking the native screen state.
WASD, Home and mouse drag could therefore reach the camera behind a training
page or modal. Input is now allowed only on the map/world page without a modal
or walking overlay. Pointer-driven zoom/drag also ignores the toolbar and map
information panel, using their current Slate geometry.

Mouse-wheel zoom now consumes `MouseWheelAxis` rather than two pressed actions.
The factor is `0.85^delta`, with packets bounded to eight steps and non-finite
values ignored. Programmatic Focus/ZoomIn/ZoomOut/ResetOverview remain available
for scene setup and the capture harness; input bindings use guarded wrappers.

Editor build `20260909T113557Z-8012858c` passed. Automation
`20260909T113603Z-981cf776` passed all 13 tests. Added assertions cover no-op,
multiple steps, opposite steps within float precision and bounded packets.
An initial compile failure from shadowing UWidget::Cursor was corrected by
renaming the local. An initial round-trip assertion used an excessively strict
default float tolerance; the corrected comparison uses 1e-6.

GPU run `20260909T113619Z-8d22e2c5` additionally asserts map input is enabled
on the city screen and disabled on the training screen. Its completion is
confirmed: all three resolutions and their process-restart checks completed,
runner exit 0. These assertions check the real UI gate;
they do not constitute an OS mouse-drag or zoom-sweep playtest.

This pass does not yet update the packaged Shipping EXE. The currently open
training-ui v2 Shipping candidate predates these camera changes. No new FPS,
flicker-resolution or GitHub publication claims.
