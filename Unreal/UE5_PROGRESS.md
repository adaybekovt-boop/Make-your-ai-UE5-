## Known issues and source-parity decisions

- UE5, UBT and an Editor rendering session are unavailable in the editing environment. No engine version can honestly be recorded as installed. Linux/Windows wrapper command construction has unit coverage, but actual UE integration on both platforms remains untested; macOS execution is explicitly unsupported by the preparation wrapper.
- The browser build retains a 615.55 kB DRACOLoader chunk warning. The baseline setup-node action emitted a runtime deprecation warning; the project itself ran on Node 22.23.2. These did not fail the checks and were not masked as UE errors.
- Migration documentation incorrectly required Git LFS. It now matches .gitattributes and the verified ordinary-Git assets. No storage migration was performed.
- The code already includes dc-north and dc-south alongside the five named base locations. Future save migration must preserve these IDs. Base-location purchase has no sequential unlock progression, so introducing a Locked enum must not silently change purchase rules.
- Procurement has two-stage price rounding, immutable atomic kit ordering and retained inventory provenance. Fractional operating cash needs an explicit fixed-point unit and rounding/accumulation policy before an int64 money port. No such policy or balance change was silently imposed.
- Source review covered the required migration docs and relevant procurement/config/initial-state files, not every system in full. Review the actual simulation clock, company-model state and save migrations before implementing their UE equivalents. [UE5_SOURCE_AUDIT.md](UE5_SOURCE_AUDIT.md) records the exact coverage and procurement rules.
- No real-time human playtest or new 1x balance run was performed. Earlier project requirements for that validation remain open; the 388-test result is not a substitute.
